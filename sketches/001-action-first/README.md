## Variant: Action First

### Design stance
The most important things the user must *do* jump off the page as full-bleed action cards at the top. Everything else (KPIs, lists, announcements) is secondary context that earns its place by recede-and-support.

### Key choices
- **Layout:** Hero greeting → 3-column "action card" row (the things requiring decisions) → quick action bar → collapsed KPI strip → 2-column main (enrollment list + sidebar with announcements/faculty)
- **Typography:** System sans, 15–16px body, 24px KPI values. Hierarchy through size and weight, not through type families.
- **Color:** Soft pastel gradient cards (red-urgent, amber-attention, indigo-default) draw the eye to decisions needed. White-and-indigo elsewhere.
- **Interaction:** Action cards lift on hover with shadow, signaling clickability. Quick action bar mirrors a "compose" toolbar. KPI strip is intentionally one-line so the eye moves past it.

### Trade-offs
- **Strong at:** Driving a chair to act on requests before they age out, getting a daily task list out of the dashboard, surfacing the top 3 things every visit
- **Weak at:** Comparing data across many items, doing deep work in this screen, accommodating power users who want all the data

### Best for
- Department chairs and schedulers whose primary job is *deciding and triaging*, not *browsing data*
- A "morning briefing" feel where the dashboard says "here's what needs you" first
- Departments where requests aging out is a real cost (registration, room conflicts, etc.)
